操作系统实验

项目基本结构

一、先理解 xv6 项目的整体结构

xv6 中有两类独立编译的程序：内核和用户程序。

内核与用户程序分别拥有自己的代码和地址空间。用户程序需要通过系统调用请求内核服务。

理解文件关系时，要区分两件事：

  • 编译关系：头文件提供类型、常量、函数声明；源文件提供实现；链接器把各部分连接起来。
  • 运行关系：CPU 执行已经编译好的指令，发生函数调用、系统调用或中断。

运行时不会因为调用一个函数而去打开它所在的 .c 文件。

二、重要文件分别负责什么

1．类型、常量和声明文件

文件 主要内容 什么时候修改
kernel/types.h uint、uint64 等基础类型 通常直接使用
kernel/riscv.h RISC-V 寄存器操作、PTE 标志、页表类型、地址转换宏 增加硬件相关定义，例如 PTE_A

kernel/proc.h struct proc、struct trapframe 等结构 给每个进程新增状态或资源指针
kernel/defs.h 内核中跨文件使用的函数声明 新增供其他内核文件调用的函数
kernel/syscall.h 系统调用编号 SYS_xxx 新增系统调用时分配唯一编号
kernel/param.h 进程数、文件数等配置限制 修改系统容量或相关限制
user/user.h 用户可以调用的系统调用和库函数声明 新增用户接口，例如 pgaccess()、ugetpid()

2．系统调用和用户库文件

文件 主要职责

user/usys.S 生成后的入口，设置编号并执行 ecall

七、编写内核功能时，按哪条路线修改文件

首先判断功能属于哪一种情况。

功能类型 典型例子 需要的路线
仅供内核调用的功能 页表遍历辅助函数 对应 .c 实现；跨文件使用时补声明
用户需要请求内核执行 pgaccess() 增加系统调用入口、编号、分发和处理函数
普通用户函数即可完成 ugetpid() 的读取部分 ulib.c 实现、user.h 声明
新增每进程资源 ugetpid() 的共享页 增加进程字段，并补齐分配、映射和回收

对于一个新的系统调用，通常按下面的顺序编写：

  1. 确定接口：用户传什么参数，返回什么结果，哪些输入应当失败。
  2. 确定数据位置：临时变量、进程字段、全局变量，或已有页表状态。
  3. 实现核心操作：页表算法放 vm.c，进程资源管理放 proc.c 等合适模块。
  4. 补跨文件声明：需要公开的内核函数写入 defs.h。
  5. 实现 sys_xxx()：在合适的系统调用文件中取参、检查参数、调用核心功能、返回结果。
  6. 注册内核入口：syscall.h 分配唯一编号，syscall.c 添加声明和分发表项；你的项目还需要 trace 名称。
  7. 建立用户入口：user.h 添加声明，usys.pl 添加 entry("xxx")。
  8. 编写用户测试并构建运行。

sys_xxx() 中的工作很短时，可以直接在里面实现，例如目前的 sys_pgaccess()。当算法较独立、较复杂，或多个地方需要使用时，再抽到对应模块。

一张页表有 512 个 PTE。对每个条目，先检查 PTE_V，无效就跳过；有效则打印索引、PTE 和物理地址，然后决定是否继续向下：

条目类型 如何识别 PTE2PA(pte) 的含义
指向下一级页表 正常情况下 R/W/X 全为 0 下一张页表的物理地址

遍历顺序是 level 2 → level 1 → level 0。普通 4 KB 页在 level 0 出现叶子；后续超级页实验会在 level 1 提前出现叶子，所以遇到叶子就停止向下递归。

目的：修改内核页表，使用 2MB 超级页代替大量 4KB 页，减少页表内存占用和 TLB miss。
• RISC-V 支持 2MB 超级页。普通页在 level 0 建立叶子 PTE，超级页则在 level 1 直接建立叶子 PTE，跳过 level 0 页表。 要点：在 level 1 PTE 上设置 PTE_V 和 PTE_R，PPN 指向 2MB 对齐的物理区域，硬件识别为叶子，翻译时跳过 level 0。超级页映射的是内核的连续物理区域（内核代码、数据、设备区），不由kalloc 逐页分配复制 mappages 专给 kvmmap 用，满足 2MB 对齐且 ≥2MB 时用超级页，不满足部分回退 4KB；原 mappages 不变，用户页表仍用 4KB 页

1．先区分普通函数调用和 Trap。

情况 怎样触发 返回位置主要保存在哪里
普通函数调用 jal、jalr 等调用指令 ra，必要时由函数保存到栈
系统调用 用户执行 ecall 硬件记录到 sepc，随后由内核保存
设备中断 设备或定时器产生中断 硬件记录到 sepc，随后保存现场
同步异常 当前指令执行发生问题，例如页故障 同样通过陷阱机制记录和处理

普通函数调用通常保持当前特权级；Trap 可能发生在用户态，也可能发生在内核态。因此讲义中“所有 Trap 都从用户态切到内核态”的说法需要限定：内核执行期间发生的 Trap，也可以在内核态处理。

本项先研究普通函数调用。后面的 Alarm 还要处理“程序在任意执行位置被中断”的情况，所以保存的现场会更完整。
